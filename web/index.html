Make a 7B model write faster by letting a tiny one guess.

A 0.5B draft model guesses the next few tokens; a 4-bit 7B target model checks them all in one pass. The text stays the same — only faster. But guessing is not free, and past a certain point it slows you down. That point is the crossover.

One round of speculative decoding

1

Draft guesses

The small model quickly proposes γ tokens, e.g. " hash" " map" ",".

2

Target verifies

The big model scores all guesses in one forward pass and keeps the longest prefix it agrees with.

3

Target adds one

It fixes the first wrong guess, or — if all were right — adds a free bonus token.

Findings

Six things we measured

01 · HOST-BOUND

The GPU was waiting on the CPU

A 0.5B draft step costs 29 ms for 1 token and 32 ms for 256. Most of it is ~940 kernel launches, so the tiny model is not cheap.

r = –
02 · CUDA GRAPHS

Replaying graphs fixed it

Record once, replay with one launch. Output identical, 4-bit model included. The draft/target cost ratio dropped sharply.

r = 0.248
03 · CROSSOVER

Every domain wants a different γ

Math and structured data love long guesses; prose likes short ones; translation never pays at all.

4 optima
04 · VERIFY STEP

γ = 3 is the worst choice

Verifying 4 tokens costs as much as verifying 13. γ=3 pays the whole jump but checks only 4 tokens.

+11 ms jump
05 · CONTROLLER

Adapting γ live did not win

Fixed γ=2 already reaches most of the oracle. The controller's lag cost more than the small headroom.

Identical, where greedy is defined

Every reproduced mismatch sits on an exact fp16 tie between the top two tokens. Zero decoder bugs.
